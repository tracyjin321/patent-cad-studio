# 图元查询与装配优化规划（2026-08-03）

## 1. 背景与目标

当前正式图元库包含 93 个图元，已覆盖传动、紧固、轴系与支承、结构件、动力执行、直线运动和航天器结构。系统已经具备 ComponentSpec v1.3、YAML/STEP 稳定转换、参数化 OpenCascade 生成、端口装配和 STEP AP214/AP242 输出能力。

当前最关键的架构缺口是：前端选择的 `component_ids` 主要用于图元存在性校验、主要对象推断和结果元数据展示，尚未真正进入 `/api/generate` 的最终 B-Rep 装配。后续优化应优先打通需求、查询、选型、装配、质量验证和交付物之间的数据闭环，再持续扩大图元数量。

目标：

- 让自然语言需求可以稳定地产生可解释、可校验的装配计划。
- 让查询命中的图元真正参与最终 STEP、3D mesh 和专利附图生成。
- 建立端口兼容、几何有效性、干涉与尺寸精度的质量门禁。
- 将高频标准件建设为参数化规格族，降低重复 STEP 维护成本。
- 保持现有 YAML-first → OpenCascade → STEP/SVG/Three.js 技术路线不变。

## 3. P0：逻辑正确性

### 3.1 `/api/generate` 真装配

现状：所选 `component_ids` 没有进入最终 B-Rep，只作为约束和展示信息。

优化：

- 将选中图元解析成 ComponentSpec 列表。
- 生成或接收结构化装配关系。
- 调用统一装配服务生成最终 Compound/XCAF 装配。
- STEP、3D mesh、SVG 和质量检查共享同一个最终 B-Rep。

验收标准：

- 所有选中图元均出现在最终 STEP 装配树或 Compound 中。
- API 返回每个组件的实例 ID、最终变换矩阵和匹配端口。
- STEP、mesh 和附图使用对象一致性测试通过。

### 3.2 需求到装配规划器

将当前“识别零件类型”扩展为“生成装配计划”：

```text
自然语言需求
  → 识别主体、子件、数量和约束
  → 查询候选 ComponentSpec
  → 参数与端口兼容性排序
  → 输出 assembly.json
  → 装配与质量验证
```

装配计划至少包含：

- 根组件和子组件。
- 组件数量和阵列规则。
- `port`、`target`、`mate_to`。
- 匹配理由和置信度。
- 未满足约束和需要人工确认的字段。

### 3.3 装配清单 Schema

使用 Pydantic 或 JSON Schema 替换未经约束的字典输入，校验：

- `target` 必须引用已加载组件。
- 组件路径必须位于允许目录。
- `port` 与 `mate_to` 必须存在。
- 不允许循环依赖。
- 应用协议只能是支持的 AP214/AP242。
- 长度和角度单位必须明确。
- 同一端口不能被重复占用，除非端口显式允许多连接。

### 3.4 端口兼容规则落地

当前 `compatible_with` 和 `allowed_mates` 主要作为规范数据保存，装配器尚未全面执行。

需要校验：

- 端口类型。
- 公称直径和尺寸容差。
- 轴向与平面方向。
- 螺纹、键槽、法兰等接口标准。
- 允许的配合方式。
- 端口占用状态。

### 3.5 单位与坐标系统一

- 入库统一转换为毫米和度。
- 保存原始单位、缩放系数和原始坐标定义。
- 拒绝尺寸数量级异常的外部 STEP。
- 明确每个图元的原点、+Z、零旋转方向和装配基准。

### 3.6 运行稳定性

- 生成请求改为带任务 ID 的持久化任务。
- 支持进度查询、取消、超时和有限重试。
- worker 异常退出后任务可恢复或明确标记失败。
- 大模型根据估算复杂度进入加权资源槽。
- 前端展示服务端错误原因，避免只显示 `Failed to fetch`。

## 4. P1：装配能力提升

### 4.1 约束类型扩展

在现有端口重合基础上增加：

- 同轴约束。
- 平面贴合。
- 固定距离和轴向偏置。
- 指定角度。
- 圆周阵列和线性阵列。
- 齿轮啮合中心距。
- 螺纹连接。
- 轴、轴承和轴承座配合。

### 4.2 装配后检查

- 实体干涉。
- 最小间隙。
- 悬空组件。
- 重复实例。
- 包围盒或尺寸数量级异常。
- 装配图连通性。
- 未使用或重复占用端口。
- 组件姿态翻转和镜像错误。

### 4.3 XCAF 语义装配

将扁平 `TopoDS_Compound + STEPControl` 逐步升级为 `XCAFDoc + STEPCAFControl`，保留：

- 装配树和零件名称。
- 零件/实例复用关系。
- 实例位姿。
- 颜色和图层。
- 产品及版本信息。

几何生成器不变，仅增强装配语义及 STEP 输出层。

### 4.4 装配可追溯性

每次装配生成以下文件：

```text
assembly.json
resolved-transforms.json
validation.json
final.step
preview.svg
preview.png
```

`resolved-transforms.json` 记录每个实例的 4×4 世界变换、匹配端口、参数和装配理由。

## 5. P1：查询与选型优化

### 5.1 搜索排序

建议字段权重：

```text
精确 ID > 标准号 > 中文名 > 英文名 > subtype > tags > description
```

支持拼写归一、同义词和模糊匹配，避免简单字符串包含造成排序不稳定。

### 5.2 结构化过滤

- 类型和子类型。
- 标准体系。
- 公称直径、长度和宽度范围。
- 螺纹规格。
- 材料。
- 端口类型。
- 参数化/固定 STEP。
- `draft/generated/reviewed/approved/deprecated` 状态。

### 5.3 规格语义解析

支持将常见表达转为结构化查询：

```text
M3×8  → diameter=3, length=8
6201  → bearing_series=6201
DN50  → nominal_diameter=50
NEMA17 → frame=NEMA17
```

### 5.4 可解释推荐

查询结果返回：

```json
{
  "component_id": "bearing-6201-open-simple",
  "score": 0.94,
  "matched": ["6201", "深沟球轴承", "内径12"],
  "warnings": []
}
```

### 5.5 无命中分流

```text
精确图元命中
  ↓ 否
参数化生成器可生成
  ↓ 否
可信外部 STEP 可导入
  ↓ 否
创建待补图元任务
```

### 5.6 catalog 缓存刷新

当前图元目录使用进程级缓存。优化为：

- catalog 修改时间变化时自动刷新；或
- 入库接口完成后显式调用缓存失效；并
- 提供管理端刷新与库存状态接口。

## 6. P1：生成质量提升

| 方向 | 优化内容 | 验收标准 |
|---|---|---|
| B-Rep 有效性 | 引入 `BRepCheck_Analyzer` | 所有正式图元无无效壳、退化边或非流形实体 |
| 几何公差 | 统一建模、布尔、测量及导出公差 | 公差策略有单一配置和测试覆盖 |
| 布尔稳定性 | 处理相切面、共面和微小边 | 多轮生成无随机布尔失败 |
| 尺寸验收 | 按类型验证关键尺寸 | 关键尺寸全部位于规格容差内 |
| 质量属性 | 输出体积、质心、面积和惯量 | STEP 往返前后质量属性稳定 |
| STEP 稳定性 | 建立工程几何签名 | 时间戳变化不影响几何一致性判断 |
| 往返验证 | YAML → STEP → 导入 → 对比 | 正式图元 CI 全覆盖 |
| 多视图附图 | 主视、俯视、侧视、轴测和局部图 | 视图完整且无空白/截断 |
| 视觉回归 | 保存基准图和轮廓指标 | 轮廓偏差超过阈值时 CI 失败 |
| 网格 LOD | 按尺度与曲率调整三角化 | 小零件保细节，大装配控制体积 |
| 参考还原评分 | 比较轮廓和特征点 | 输出可追溯的相似度报告 |

## 7. 图元补充规划

### 7.1 第一优先级：高频机械装配

- M2–M12 螺栓、螺母、平垫和弹垫参数化规格族。
- 6000–6208 深沟球轴承系列。
- 角接触轴承、圆锥滚子轴承、推力轴承。
- O 型圈、挡圈、轴用/孔用卡簧。
- 平键、花键、弹性销、开口销。
- 标准轴承座和法兰轴承座。
- 通用阶梯轴、空心轴、花键轴。
- PN/DN 标准法兰。
- 直管、弯头、三通、异径接头。
- 梅花、膜片、波纹管和万向联轴器。

原则：优先做参数化规格族，避免为每个尺寸复制一套固定 STEP。

### 7.2 第二优先级：动力与自动化

- NEMA23/NEMA34 步进电机。
- 伺服电机及安装法兰。
- 行星减速器和谐波减速器。
- 电动缸、气缸和液压缸。
- 滚珠丝杠支撑座 BK/BF。
- MGN9/MGN12/HGR 直线导轨。
- 同步带及链条的实体/简化模型。

### 7.3 第三优先级：航天器结构

将 Falcon 9 复合图元进一步原子化：

- `merlin-1d-sea-level`
- `merlin-1d-vacuum`
- `falcon9-landing-leg`
- `falcon9-grid-fin`
- `falcon9-octaweb`
- `falcon9-stage-barrel`
- `falcon9-interstage-actuator`
- `falcon9-fairing-half`
- `falcon9-payload-adapter`
- `falcon9-feedline`
- `falcon9-avionics-ring`

原子化后可复用于其他火箭模型和不同构型，而不是只能复用整套 Falcon 9 子装配。

## 8. Falcon 9 专项质量提升

- 整流罩拆分为真正独立的左右半壳，并保留 0.5 mm 分离间隙。
- 提供着陆腿展开和折叠两个配置。
- 增加栅格翼转轴、安装座和展开角度。
- 将海平面 Merlin 与真空 Merlin 建成独立正式图元。
- 增加 Octaweb、发动机热防护罩和真空喷管加强筋。
- 增加级间段分离推杆、箱间段和推进剂箱结构分界。
- 增加 COPV、外置管路、电缆槽、载荷适配器和分离环。
- 建立关键特征位置、数量和整体轮廓的专项自动验证。

## 9. P2：图元治理

- 每个图元记录来源、许可证、标准号和原始下载地址。
- 建立 `draft/generated/reviewed/approved/deprecated` 状态流转。
- 禁止修改 `reference.step` 后不更新 SHA-256 和几何签名。
- 建立图元版本兼容规则，避免同一 ID 静默改变几何。
- catalog 由 CI 自动重建，检查重复 ID、目录名和规范错误。
- 旧 ID 使用迁移映射，不直接删除。
- 每个图元自动生成缩略图、三视图和尺寸摘要。
- 外部 STEP 增加文件大小、实体数、异常尺寸和解析资源限制。

## 10. 测试与质量门禁

### 10.1 单元测试

- 查询字段权重与过滤。
- 单位归一和规格解析。
- 端口坐标正交、方向和兼容性。
- 装配矩阵及多级变换传播。
- 清单越界、缺端口、重复端口和循环依赖。

### 10.2 集成测试

- 自然语言 → 推荐 → 查询 → 装配计划。
- `component_ids` → 最终 B-Rep 真装配。
- STEP、mesh、SVG 使用同一对象。
- AP214/AP242 输出及往返验证。
- worker 异常、取消、超时和重试。

### 10.3 图元库 CI

每个正式图元执行：

1. ComponentSpec Schema 校验。
2. reference STEP SHA-256 校验。
3. B-Rep 有效性检查。
4. STEP 往返几何检查。
5. 关键尺寸和质量属性检查。
6. 缩略图及多视图生成。
7. catalog 一致性检查。

## 11. 分阶段实施顺序

### 阶段一：装配闭环

1. 为 assembly manifest 建立正式 Schema。
2. 让 `component_ids` 真正进入 `/api/generate` 装配。
3. 执行端口兼容和占用规则。
4. 输出解析后的实例变换和装配报告。
5. 增加真实多图元 API 集成测试。

完成定义：前端选择轴、轴承和联轴器后，最终 STEP 中出现三者且端口装配正确。

### 阶段二：质量与稳定性

1. B-Rep 有效性和干涉检查。
2. 尺寸、间隙及质量属性检查。
3. 任务化生成、取消、超时和 worker 恢复。
4. 自适应网格 LOD 和大装配缓存。
5. 全图元 CI 门禁。

完成定义：非法装配在导出前失败；worker 异常不会表现为不可解释的网络错误。

#### 阶段一、阶段二实施记录（2026-08-03）

- 已引入 `AssemblyManifest 1.0` 强类型 Schema，限制 AP214/AP242、毫米单位、组件数量、依赖顺序和未知字段，并执行端口类型、配合方式、接口属性及占用校验。
- `/api/generate` 已将 `component_ids` 解析为真实装配清单；STEP、SVG 和 Three.js 网格共享同一最终 B-Rep，并返回实例 4×4 世界变换、配合端口、几何指纹和装配质量报告。
- 轴、轴承和刚性联轴器的真实 API 集成测试会下载并重新解析最终 STEP，验证三者实体及端口变换均进入交付物。
- 导出前已执行 B-Rep、两两间隙、实体干涉、包围盒、拓扑、体积、表面积和质心检查；非法重叠装配会直接失败。
- 生成已任务化，支持查询、取消、超时、持久化和进程重启后的中断任务恢复；前端轮询明确状态与错误原因。
- 网格精度会根据模型包围盒自适应调整，大装配使用清单指纹缓存 STEP 和质量报告。
- 新增全图元 CI 门禁，覆盖 93 个正式图元的 Schema、SHA-256、B-Rep、STEP 往返和 catalog 一致性检查。

### 阶段三：查询与图元扩展

1. 结构化搜索、排序和推荐解释。
2. 高频标准件参数化规格族。
3. 动力与自动化图元补充。
4. Falcon 9 图元原子化。
5. 自动入库、审核和版本治理。

完成定义：新需求可以自动命中、参数化生成或进入明确的待补图元流程。

### 阶段四：语义装配与质量评分

1. XCAF 装配树和实例复用。
2. 多视图与视觉回归。
3. 参考图轮廓和关键特征评分。
4. 装配质量综合评分与人工审核界面。

## 12. 推荐的近期执行范围

近期迭代优先完成以下五项：

1. `/api/generate` 真装配。
2. 装配清单 Schema 与端口兼容校验。
3. B-Rep 有效性、碰撞和间隙检查。
4. worker 崩溃后的任务恢复和错误展示。
5. 高频标准件参数化规格族。

在这五项完成前，不建议以增加固定 STEP 数量作为主要成功指标。核心指标应改为：需求命中率、自动装配成功率、质量门禁通过率、生成稳定性和正式图元复用率。
